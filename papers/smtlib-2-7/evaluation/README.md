# Linking SMT-LIB 2.7 to BSmtLib's Lean, and scoring the links

Without seeing the authors' citations, GPT-6.1 named the exact Appendix B rule for 73 of
the 81 cited definitions, reading only their code. From the standard to the Lean, it named
the authors' definition on 62 of 63 cited passages. It caught all 12 one-detail changes we
made to the Lean, with no false alarms on 5 untouched definitions.

BSmtLib (Jan Onderka, Armin Biere, Henrik Böving) formalises a reading of the SMT-LIB
standard's syntax in Lean. Its authors cite the standard in their documentation comments
(`Standard: 2.7 §3.1 Digits; App. B ⟨digit⟩.`). They also record twelve Readings: the places
where the standard is silent, ambiguous or contradictory and they had to decide.

This folder asks whether a model can find those links without seeing the citations, and
scores its answers against the citations themselves.

## Results

All counts are in the score files below and in [summary.json](summary.json), which the page
shows. `make_summary.py` writes it from the score files.

| Measure | GPT, code only | GPT, with comments | Names only | Everything |
| --- | --- | --- | --- | --- |
| Rule each definition states, named exactly | 73 of 81 | 65 of 81 | 60 of 81 | 81 of 81 |
| Cited prose paragraph found | 22 of 106 | 100 of 106 | 61 of 106 | 106 of 106 |
| Definitions with every citation found | 16 of 105 | 83 of 105 | 61 of 105 | 105 of 105 |
| Linked rules the authors cite | 88 of 100 | 80 of 88 | 111 of 112 | 7572 of 43036 |
| From the standard: the authors' definition named | 62 of 63 | | 55 of 63 | |
| Readings explained | 4 of 12 (2 more in part) | 7 of 12 (2 more in part) | | |

- **GPT, code only**: GPT-6.1 reading the Lean with every comment removed.
- **GPT, with comments**: GPT-6.1 reading the Lean with the authors' comments kept, minus every
  paragraph that cites the standard, names a Reading or carries a tag.
- **Names only**: no model. Each definition is linked to the 2.7 rule that has its name
  (`simpleSymbol` to ⟨simple_symbol⟩), and to paragraphs whose heading names it.
- **Everything**: a control that links every passage to every definition.

**Meaning test.** We changed one detail in each of 12 definitions: a character range, a
release, or a list allowed to be empty. Two fresh sessions were each asked whether each
definition states its passages exactly. GPT-6.1 caught all 12 changes, and for each one named
an input the changed Lean treats differently. It called all 5 untouched definitions exact. It
also flagged 3 definitions we meant to leave untouched, because they use one we changed
(`decimal` uses `digit`), and it named the effect. See `meaning/score.json`.

## What these numbers do not show

- **This is not independent confirmation.** The authors' paper says their formalised reading
  was generated by AI and reviewed by the maintainer. GPT-6.1 is a different model family from
  the one the paper names, but agreement is still not proof that either side is right.
- **The authors' citations are the reference, not the truth.** A run's link that the authors do
  not cite is listed for review in the score files. It is not counted as wrong.
- **Readings were graded by Claude with the authors' words visible**
  (`runs/reading_grades.json`, `meaning/reading_grades.json`), so those grades are a reviewed
  judgement, not a blind measurement. In the run with comments kept, some comments that cite
  nothing still state the authors' choice. For example, `modeAfter`'s comment says
  "`reset` among them, leaves the mode as it is". That run partly read Readings rather than
  found them.
- **Known faults in our own inputs:**
  - The text extraction of the 2.0 PDF drops some underscores.
  - One list of example attributes was split as prose.
  - The meaning test's L6 item left out Appendix B's reserved-word list, so L6 was not tested
    there.
  - In meaning session 1, the Reading items used `digit`, which that session changed.
- **One run per condition.** There is no measure of variation between runs.

## How it was run

1. `inventory.py` split the four releases into 1,403 passages, each with its page, section,
   run-in heading, kind and grammar rule. Each passage was anchored on its page with Proof
   Reader's own quote finder. The split was frozen before any run (`inventory/FROZEN.json`).
2. `reference/key_rows.json` holds the authors' 159 tagged comments, of which 106 cite the
   standard. A Type B review audited and corrected the regular-expression extraction. Then
   `scoring.py reference` turned each citation into groups of passages.
3. `prepare_runs.py` made the two inputs: code only, and comments kept minus citations. In both
   the namespace is renamed and the authors' list of Readings is left out. A residual scan stops
   the build if any citation survives.
4. `run_matcher.py` ran each task in a fresh Codex session (GPT-6.1, reasoning effort high,
   Codex CLI 0.162.1). Each session had an empty home folder, so no personal instructions or
   skills; the workspace-write sandbox; and no network. The prompts are in `tasks/`. Every
   command each session ran is in its `.audit.json` and `.events.jsonl.gz`, and the audit checks
   them for paths outside the session's folder. None read outside it.
5. `scoring.py score` and `scoring.py score-passages` scored the runs. `test_scoring.py` checks
   that the scorer gives nothing to predictions that know nothing: every passage everywhere,
   nothing, one easy row, random passages, and a bare section number.
6. `meaning_test.py` built the meaning test, and `score_meaning.py` scored it. The scorer counts
   a change wherever Lean's own dependency report carries it.
7. `build_links.py` wrote the page's `links.json`. A passage is linked to a definition when a
   run found the link, or when the authors cite exactly that rule or heading. Each link records
   which runs found it and whether the authors cite that passage, the same text as another
   release prints it, another passage, or none.

To rerun the scoring:

```sh
python3 papers/smtlib-2-7/evaluation/scoring.py reference
python3 -m unittest papers/smtlib-2-7/evaluation/test_scoring.py
python3 papers/smtlib-2-7/evaluation/make_summary.py
```
